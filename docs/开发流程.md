# 从零构建：这个项目的开发流程

> 这份文档回答两个问题：
> 1. 这个桌宠是怎么一步步做出来的？
> 2. 换一个项目，同样的流程怎么复用？

## 1. 先跑通“最薄的一条完整路径”

不要一上来就做全部功能。先让一条最细的链路跑通：

```
浏览器打开 index.html → 看到一只大鼠 → 点一下有反应
```

这条链路已经包含了：HTML 结构、CSS 样式、JS 事件、文件路径。
它跑通之后，再往上加 Electron 窗口、托盘、位置记忆、打包。

这叫 **walking skeleton（会走路的骨架）**：先让它站起来，再让它跑。

## 2. 五层架构

| 层 | 文件 | 运行环境 | 职责 |
| --- | --- | --- | --- |
| 页面 | `index.html` / `style.css` / `pet.js` | Chromium | 画角色、动画、点击 |
| 桥 | `electron/preload.js` | 预加载脚本 | 只暴露 `petAPI` 四个函数 |
| 主进程 | `electron/main.js` | Node.js | 窗口、托盘、位置、菜单、退出 |
| 运行时 | Electron | 打包进安装包 | Chromium + Node |
| 分发 | `electron-builder` | 构建机 | 安装包、图标、快捷方式 |

## 3. 层与层之间的“合同”

每一层只通过明确的接口说话，这就是架构：

- **DOM**：`#pet`、`#petInner`、`#bubble`
- **桥**：`window.petAPI.startDrag / dragTo / endDrag / showMenu`
- **IPC**：`drag:start`、`drag:move`、`drag:end`、`menu:show`
- **打包**：`package.json` 里的 `main`、`build.files`、`build.win.icon`
- **资源**：`assets/` 下的 `icon.ico`、`tray.png`

改任何一边，都要检查另一边。比如把 `petAPI` 改名，`preload.js` 和 `pet.js` 必须一起改。

## 4. 开发循环

```
改代码 → 启动 → 观察 → 提交
```

- 网页版：按 F5 刷新
- 桌面版：托盘退出 → 双击 `启动桌宠.cmd`
- 提交：`git add .` → `git commit -m "..."` → `git push`

小步提交，比“憋一个大版本”安全得多。

## 5. 调试方法（以 Electron 启动崩溃为例）

1. **复现**：记录现象（没有窗口）、退出码（`0xC0000005`）
2. **最小化**：写一个只开空白窗口的测试
3. **对照**：VS Code 也是 Electron，它能跑 → 系统本身没问题
4. **隔离**：换 Electron 版本、换启动参数、换目录
5. **校验**：对比安装包哈希，排除“包坏了”
6. **回归**：修好后把拖动、位置、单实例都测一遍

结论：不要一上来改代码。先把“可能性空间”缩小，再动手。

## 6. 打包发布

```powershell
npm run dist
```

产物：`dist/MeijiRatPet-Setup-0.3.1.exe`

版本号规则：`主版本.次版本.修订号`，比如 `0.3.1`。
打标签：

```powershell
git tag -a v0.3.1 -m "修复拖动越界"
git push origin v0.3.1
```

发布：把 exe 上传到 GitHub 的 Releases 页面。

## 7. 从零重来的命令清单

```powershell
# 1. 建项目
mkdir meiji-rat-pet
cd meiji-rat-pet

# 2. 网页骨架（手写 index.html / style.css / pet.js）
#    双击 index.html，确认能跑

# 3. 接入 Electron
npm init -y
npm install --save-dev electron
#    创建 electron/main.js 和 electron/preload.js
#    在 package.json 里设置 "main" 和 "start"

# 4. 跑起来
npm start

# 5. 加桌面能力（托盘、位置记忆、单实例）

# 6. 打包
npm install --save-dev electron-builder
npm run dist
```

## 8. AI 时代，人负责什么

AI 可以很快地写出代码，但它不能替你决定：

- **要做什么**：需求和验收标准
- **怎么分层**：哪些逻辑放主进程，哪些放渲染进程
- **接口长什么样**：`petAPI` 暴露什么，IPC 有哪些消息
- **什么算做对了**：跑起来、点得动、拖得走、关得掉
- **什么时候发布、出问题怎么回滚**

一句话：**AI 写实现，人管边界和验证。**

## 9. 验收清单

- [ ] 网页版能打开、能点、能拖
- [ ] 桌面版窗口透明、置顶、无边框
- [ ] 拖动不跑出屏幕
- [ ] 重启后回到上次位置
- [ ] 双击两次只有一只
- [ ] 托盘能显示/隐藏、能退出
- [ ] 打包后的 exe 能启动
- [ ] README 和 CHANGELOG 是最新的
